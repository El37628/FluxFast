# v1.0 protocol stability proof

FluxFast 1.0 continues the exact `fluxfast/1` wire contract adopted in v0.9.0.
This gate changes no wire field, capability, header meaning, patch operation,
or protocol identifier. Package versions remain independent from the protocol
version.

## Frozen semantic baseline

[`tests/fixtures/protocol-v1-v0.9.0.json`](../../tests/fixtures/protocol-v1-v0.9.0.json)
records the v0.9.0 contract facts and canonical SHA-256 digests for every shared
golden fixture. Canonicalization sorts object keys and preserves array order,
so the gate detects semantic payload changes without depending on JSON
formatting.

The shared fixtures cover:

| Contract behavior | Fixture evidence |
| --- | --- |
| Normal page and known-version omission | `normal-page.json`, `known-version-delta.json` |
| Partial and deferred resources | `partial-resource-load.json`, `deferred-page.json`, `deferred-error.json` |
| Resource failure and validation failure | `resource-error.json`, `validation-error.json` |
| Live page negotiation | `live-page.json` |
| Patch and invalidation mutations | `mutation-patch.json`, `mutation-invalidation.json` |
| Internal and external redirects | `redirect.json`, `external-redirect.json` |

Python validates and losslessly round-trips every fixture through its producer
models. Core validates the same payloads through the browser consumer and
exercises the error mappings. Both runtimes compare protocol identity,
capabilities, header names, bounds, patch operations, and live-event facts with
the same baseline.

## Stable headers and bounds

The baseline freezes `Accept`, `X-FluxFast`, `X-FluxFast-Protocol`,
`X-FluxFast-Visit`, `X-FluxFast-Known`, `X-FluxFast-Only`,
`X-FluxFast-Capabilities`, `X-FluxFast-Client-ID`, `X-FluxFast-Live`,
`X-FluxFast-Live-Keys`, and `X-FluxFast-Live-Resources`.

The v0.9 limits remain exact: 100 known resources, 16 KiB decoded known data,
128-character resource keys and versions, 16 KiB partial/live-key headers, 100
live keys, a 2,048-byte and 32-token capability header with 64-character tokens,
a 64-character client ID, and a 1 MiB browser live-event frame. Existing
invalid-input fallbacks and rejection behavior remain unchanged.

## Capabilities and live semantics

Only `deferred-resources` and `live-resources` are negotiated. Reaching package
version 1.0 does not add a capability. Live traffic retains the `fluxfast` SSE
event name; `ready`, `invalidate`, `patch`, and `resync` event types; and the
`overflow`, `reconnect`, `broker-recovery`, and `server` resynchronization
reasons.

The release test also scans the protocol implementations for v0.9.0 or v1.0.0
package-version branches. Any future incompatible semantic change must use a
new protocol version rather than reinterpret `fluxfast/1`.

## Verification

The proof is exercised by:

```text
node --test scripts/protocol-stability.test.mjs
pnpm --filter @fluxfast/core test
pytest python/fluxfast/tests/test_protocol_fixtures.py
```
