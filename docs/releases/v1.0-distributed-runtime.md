# v1.0 distributed runtime final gate

This gate promotes the existing v0.9 distributed contract. It adds correctness
evidence and fixes request injection; it changes no public signature, protocol,
schema, cache identity, live event, or Redis server support range.

## Cross-worker coherence

`test_four_fastapi_workers_share_invalidation_live_refresh_and_refill` starts
four independent, actual Uvicorn processes using one Redis deployment:

1. A loads the positive-TTL counter into the shared cache.
2. B returns the identical record/version without another loader call.
3. D opens a live stream; opening it does not execute the loader.
4. C mutates canonical state, invalidates the cache and publishes via Redis.
5. D receives the invalidation and performs the canonical resource-only reload.
6. B returns the identical fresh record/version with no extra loader call.

The test checks four distinct operating-system PIDs and HTTP worker headers,
both record versions, and the exact shared loader count: one before mutation,
two after refill, and still two after the later warm hit.

`production-distributed.spec.ts` separately runs the actual `fluxfast start`
supervisor, three-worker Uvicorn pool, optimized Next production build, and
Chromium through one public origin. It proves distinct loader/cache-reader/
mutation roles, two-browser live convergence, changed canonical versions, and
subsequent fresh warm hits without additional loader work. It allows duplicate
concurrent cold loads, as the frozen contract has no distributed single-flight
lease.

## Failures and isolation

| Requirement | Direct evidence |
| --- | --- |
| Redis absent at startup | Three real workers remain not-ready, return a visible cache error, never invoke the loader, and shut down without forced kill. |
| Cache connection drops | Kill only the run's authenticated cache connections; another worker reconnects and returns the unchanged shared record without loading. |
| Cache command fails | Real Redis denies the test user's transaction and invalidation commands; reads/deletes return explicit errors, failed reads do not load, and failed invalidations do not publish. |
| Publication fails | Real Redis independently denies the test broker's publication command; business mutation remains successful, publication errors increment, and a different worker reloads fresh canonical state after cache deletion. |
| Missed signal and canonical resync | Change canonical state without publishing, delete its cache entry, and drop only the deployment's named Pub/Sub connections. An actual production browser reconnects and displays the new state through canonical reload. |
| Actual outage and restart | Stop and restart the explicitly selected isolated Redis container; cache errors remain visible while down and fresh subscriptions/cache writes recover afterward. |
| Shutdown while Redis is down | Close the application's owned cache/broker after its active streams disconnect, before restarting the stopped container; cleanup is bounded and readiness stays false. |
| User and tenant isolation | Real worker HTTP streams and three production browser contexts with distinct opaque session cookies prove separate user resources, shared same-tenant resources, different-tenant resources, and scope-derived event delivery. |
| Forged browser authority | Alleged scope/user headers, query fields, mutation fields, internal cache identities and opaque live topics cannot replace authenticated identity. An undeclared tenant secret is excluded from mixed subscriptions and rejected when requested alone. |
| Anonymous/logout transition | Unauthenticated page, live and mutation requests are rejected; clearing a production browser's cookie makes subsequent scoped reads unauthorized. |

The session maps are **test application authentication fixtures**, not a
FluxFast authentication provider. The application still owns identity and
authorization. Test helpers create and delete only unique temporary Redis ACL
users, kill only their connections or the isolated deployment's named Pub/Sub
connections, and clear only UUID-qualified diagnostic keys/cache namespaces.
They do not flush the Redis database or change existing users' credentials.

The request-injection regressions failed before the fix for page and mutation
handlers using postponed `Request`, postponed aliases, and postponed
`Annotated[Request, ...]`. The router now uses FastAPI's own annotation
resolution to recognize the existing request rather than injecting a second
parameter. Both cookie authority and a separate postponed Pydantic mutation
input are retained, including wrapped handlers.

Publication is still best-effort and Pub/Sub is still ephemeral. No durable
event delivery is claimed. If a business mutation commits but shared cache
invalidation fails, its request fails explicitly; the application must arrange
recovery/retry of invalidation. The gate does not claim automatic transaction
rollback or a local-cache fallback.

## Redis matrix and repeatable checks

Supported Redis Open Source server lines remain **6.2 through 8.10**. Both
compatibility jobs now identify their service container so the actual restart
test runs rather than silently skipping. Images remain
`redis:6.2.24-alpine3.21` and `redis:8.10.1-alpine3.23`; the normal production
browser job retains Redis 7.4. The optional `redis-py` client range is separate
and remains the manifest's `>=5.0.0,<9.0.0`.

With a dedicated Redis service, run:

```bash
FLUXFAST_TEST_REDIS_URL=redis://127.0.0.1:6379/15 \
  .venv/bin/python -m pytest -q python/fluxfast/tests
pnpm test
pnpm typecheck
FLUXFAST_TEST_REDIS_URL=redis://127.0.0.1:6379/15 pnpm test:e2e:distributed
FLUXFAST_TEST_REDIS_URL=redis://127.0.0.1:6379/15 pnpm test:e2e:distributed:production
```

For **each** supported endpoint, run the following against its own disposable
container; never select a shared or production Redis container:

```bash
FLUXFAST_TEST_REDIS_URL=redis://127.0.0.1:PORT/15 \
FLUXFAST_TEST_REDIS_CONTAINER=EXACT_TEST_CONTAINER_ID \
FLUXFAST_TEST_REDIS_CONTAINER_ENGINE=podman \
  .venv/bin/python -m pytest -q \
    python/fluxfast/tests/test_live_redis_integration.py \
    python/fluxfast/tests/test_redis_cache_integration.py \
    python/fluxfast/tests/test_redis_multiworker_integration.py
```

Omit the engine setting for Docker, as CI does. The restart test intentionally
stops that exact container and restores it in cleanup.

Local evidence: 693 Python tests passed with one explicit container-restart
skip in the ordinary full run; **29 integration tests passed without skips on
each of Redis 6.2.24 and 8.10.1**, including actual restart and outage shutdown.
Core/Next tests and all public-API/schema compatibility gates passed; all three
supervised production distributed Chromium scenarios and all 20 broader
production critical/deferred/live scenarios passed. The new live-isolation
tests observe actual Redis subscribe acknowledgements before publishing, not
only the asynchronously emitted SSE ready frame.
