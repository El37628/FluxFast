# FluxFast 0.9.0 Freeze Audit

This audit reviews the complete `v0.8.1...HEAD` release-candidate diff in the
same implementation session, as required by `NEXT_PHASE.md`. It evaluates the
candidate against the public API, protocol, schema, generated API, runtime,
security, and release contracts established for v0.9.

## Result

No P0 findings were identified. Two P1 findings and one trivial P2 finding were
identified and resolved in the release candidate. There are no known unresolved
P0 or P1 findings.

## Findings

### P1: destroyed routers retained pending prefetch work

`FluxRouter.destroy()` stopped visits, deferred loads, live work, history, and
event listeners, but did not clear the prefetch manager. A transport that stayed
pending could retain the destroyed router and complete outside its lifecycle.

Resolution: router destruction now clears the prefetch manager, aborting its
controllers and discarding its in-flight and cached entries. A regression test
proves the transport signal is aborted and the abandoned request produces no
pending or page-cache entry.

### P1: an older prefetch could cache a stale page shell

The resource epoch guard correctly prevented an older prefetch response from
overwriting a newer shared resource. The same response could nevertheless
populate `PageCache` with its older component metadata while recording the
newer resource version, making the stale shell appear valid during history
restoration.

Resolution: a prefetch response may populate `PageCache` only when none of its
declared resource dependencies advanced after the request began. The existing
resource winner remains authoritative, and a regression test proves the losing
page response is absent from both prefetch and page caches.

### P2: external redirect wording was broader than validation

The protocol guide called `externalRedirect` an absolute destination, while the
frozen implementation accepts absolute HTTP(S) destinations. The guide now
states the exact HTTP(S) contract.

## Reviewed contracts

- Public API: Python exports and important call signatures, all reviewed Core
  root exports, all five Next package entry points, CommonJS/ESM declarations,
  and npm export-map boundaries.
- Protocol: `fluxfast/1` identity and envelopes, headers, capabilities, patch
  operations, redirects, mixed-version behavior, and optional `appVersion`
  metadata.
- Schema: the closed `fluxfast-schema/2` shape, deterministic fingerprints,
  schema/1 reader compatibility, and cross-runtime golden fixtures.
- Generated API: filenames, semantic exports, identifier rules, validators,
  determinism, drift checks, and per-file atomic replacement.
- Runtime: resource and page-cache coherence, mutation and navigation races,
  deferred and live lifecycles, multi-worker Redis coordination, production
  startup, cleanup, and bounded memory/in-flight state.
- Security: scope isolation, path containment, header and parser bounds,
  validation limits, redirect normalization, schema parsing, dependency review,
  CodeQL, and release provenance policy.
- Release: clean packed consumers, upgrade-order and rollback coverage,
  mixed-version consumers, platform matrices, benchmarks, documentation gates,
  artifact contents, checksums, and publication verification.

## Local validation

- Python: 616 passed, 23 environment-gated skips; Ruff passed.
- Core/Next: 527 tests passed; release-script and schema/1 compatibility tests
  passed; TypeScript typechecking passed.
- Browser: 17 development-mode tests passed with 2 production-only skips; all
  19 production-mode tests passed.
- Distributed: development and production three-worker Redis browser tests
  passed.
- Consumers: clean initialization, clean packed production, and the published
  0.8.1 distributed baseline passed. Release-candidate upgrade-order, rollback,
  and full packed-consumer matrices remain mandatory PR checks.
- Performance: request/cache, deferred, live, Redis, code-generation,
  validation, retained-memory, production-bundle, and multi-worker production
  lifecycle benchmarks all passed their correctness gates without an
  unexplained hot-path regression.
- Artifacts: the Python wheel and source distribution plus both npm tarballs
  passed the metadata, contents, and SHA-256 checksum verifier.

The pull request must also pass the repository's complete required GitHub check
set, including the supported Python, Node.js, and Next.js matrices, container
tests, dependency review, CodeQL, release artifacts, upgrade-order consumers,
and the full packed release-candidate consumer before merge.
