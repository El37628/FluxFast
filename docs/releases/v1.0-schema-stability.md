# v1.0 developer schema stability proof

FluxFast 1.0 continues the closed `fluxfast-schema/2` developer-manifest
contract adopted before v0.9.0. The package version changes independently from
the schema version.

## Producer-only candidate delta

[`developer-schema-v2-v0.9.0.json`](../../tests/fixtures/schema/developer-schema-v2-v0.9.0.json)
pins the v0.9.0 golden manifest's canonical SHA-256 digest and semantic
fingerprint. Python builds the same application contract twice: once as the
v0.9.0 golden fixture and once with the v1.0.0 candidate producer.

The candidate manifest must equal the complete v0.9.0 fixture after exactly
this metadata substitution:

```text
producer: 0.9.0 -> 1.0.0
```

The `schema`, `fingerprint`, `types`, `resources`, `pages`, and `mutations`
values remain identical. The independently pinned canonical digest prevents a
regenerated fixture from passing solely because the producer changed with it;
any baseline change must also update the separate digest record explicitly.

## Reader and producer matrix

| Contract | v1.0 evidence |
| --- | --- |
| `fluxfast-schema/1` reader | The legacy fixture is parsed and compiled into resource types, validators, routes, and mutation helpers; the full compatibility script generates, typechecks, and builds it. |
| `fluxfast-schema/2` reader | The v0.9.0 fixture is parsed and consumed by every TypeScript compiler. |
| `fluxfast-schema/2` producer | Python reproduces the complete v0.9.0 fixture and the exact producer-only v1.0.0 candidate. |
| Closed schema/2 shape | Python model inventories and TypeScript unknown-field tests freeze every structural level. |

The supported reader set remains exactly `fluxfast-schema/1` and
`fluxfast-schema/2`. A v1.0.0 producer still emits schema/2, and both runtimes
reject `fluxfast-schema/3`; no schema/3 contract is introduced by the package
major-version promotion.

## Fingerprint invariant

The semantic fingerprint excludes `producer` and `fingerprint` metadata. For
an unchanged application contract, the v0.9.0 and v1.0.0 manifests therefore
retain the same digest. Existing tests separately prove that changes to a type,
resource, page parameter, mutation method, or mutation body change the digest.

## Verification
