# v1.0 generated-contract compatibility proof

FluxFast 1.0 retains the generated TypeScript contract shipped by the v0.9.0
`@fluxfast/next` generator. The gate uses one schema/2 application fixture and
one component tree for both versions.

## v0.9.0 baseline

[`generated-contract-v0.9.0.json`](../../tests/fixtures/generated-contract-v0.9.0.json)
records the output of `@fluxfast/next@0.9.0`. It contains:

- the complete generated filename set;
- comment- and whitespace-insensitive fingerprints for every generated
  TypeScript source file; and
- a readable inventory of domain interfaces, resource aliases, resource keys,
  generated and augmented resource-map entries, validators, route builders,
  mutation helpers, page exports, and component registry identifiers.

The fixture uses `fluxfast-schema/2`, a typed `rooms` resource, explicit input
and user contracts, one parameterized page route, one typed mutation, and the
`hotel_rooms/index` component.

## v1.0 candidate comparison

The candidate generator receives the same manifest and component tree. Only
the manifest's producer metadata changes from `0.9.0` to `1.0.0`; the
developer-schema stability gate separately proves that this does not change
the schema fingerprint.

Both the v0.9 reference generation and the v1 candidate must equal the checked
baseline. The readable inventory directly freezes the application-facing
names and mappings, while normalized source fingerprints catch signature or
implementation drift without treating comments or whitespace as contract
changes. The promotion intentionally also retains declaration and object
ordering; a future intentional reorder requires an explicit baseline review.

The existing generated-contract consumer then typechecks every documented
interface, alias, map augmentation, validator, route call, mutation call, and
component registry access together.
