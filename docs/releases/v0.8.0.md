# FluxFast 0.8.0 Release Notes

> **Release Theme:** General Application Contracts & Native Client Validation

FluxFast 0.8 expands server-owned contracts into general application models
and introduces a first-party, dependency-free client validation system generated
from the same source of truth.

---

## Headline Features

### 1. General Application Contracts (`define_type`)

Define authoritative application models in Python with Pydantic and consume their
generated TypeScript interfaces anywhere in your frontend:
- Components, hooks, utilities, stores, and test fixtures can share server-owned
  types without requiring page resource declarations.
- Explicit support for `mode="serialization"` (server output) and
  `mode="validation"` (client input).
- Declarations live on the application's `FluxFast` instance with duplicate
  detection.

### 2. `fluxfast-schema/2` Developer Manifest

A versioned developer manifest specification introducing:
- Top-level `types` dictionary for explicit general contracts.
- Reusable mutation input schemas.
- Canonical SHA-256 fingerprint calculated over sorted, deterministic contract
  definitions for reliable drift detection in CI.
- Backward-compatible reader in `@fluxfast/next` 0.8 that can process legacy
  `fluxfast-schema/1` manifests.

### 3. Unified Type Graph Compiler

Refactored framework-neutral compiler that compiles general types, resources,
mutation bodies, and `$defs` into a single coherent TypeScript definition graph:
- Global schema deduplication to shared interfaces.
- Collision detection with clear generation errors on conflicting names.
- Explicit contract names always take precedence over inferred model titles.
- Backwards compatibility: Existing imports from `@/.fluxfast/types.generated`
  (`resourceKeys`, `FluxResourceMap`) remain unchanged.

### 4. Reusable Mutation Request Bodies

Mutation request bodies generate named interfaces (`${PascalCase}Body`) in
`types.generated.ts` instead of inline object literals. Mutation helpers in
`mutations.generated.ts` consume these interfaces directly.

### 5. Native Validation Runtime (`@fluxfast/core`)

A framework-neutral, lightweight client validation engine built into
`@fluxfast/core`:
- Zero external runtime dependencies (no Zod, Valibot, Yup, Joi, or AJV).
- Pure, tree-shakeable validator construction in
  `@/.fluxfast/validators.generated.ts`.
- Structured `ValidationResult<T>` with `ValidationIssue` entries, canonical error
  codes, and dot/bracket path formatting (`formatValidationPath`).
- Hardened execution limits (`maxDepth`, `maxOperations`, `maxIssues`), prototype
  pollution immunity, and cyclic object detection.

### 6. Synchronous Validator Refinements (`refineValidator`)

Minimal validator composition allowing custom cross-field validation rules
(e.g., password confirmation) that run only after structural schema validation
passes.

### 7. Pre-Submit Form Validation with `useForm`

`@fluxfast/next`'s `useForm` hook integrates directly with generated validators:
- `useForm(data, { validator: MyValidator })` runs validation synchronously before
  submitting.
- Zero network requests sent if client data is invalid.
- Exposes `form.validate()`, `form.errors`, `form.issues`, and dot-path
  `form.errorMap`.
- Seamlessly merges client validation issues with authoritative FastAPI 422
  server responses.
