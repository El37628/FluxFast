# v1.0 client concurrency authority gate

The v1.0 promotion reruns the client races that can otherwise restore old
resources, page shells, redirects, or live state. The gate belongs to
framework-neutral Core; no wire field, capability, or public API changes.

## Repeatable workload

`packages/core/tests/client-authority-stress.test.ts` uses controlled promises
and streams rather than wall-clock sleeps. The transport intentionally ignores
abort signals, proving late-result rejection independently from fetch's
cancellation behavior. Each repeated race runs 20 cycles, and fake timers drive
live batching and reconnect readiness deterministically.

| Required combination | Assertion |
| --- | --- |
| Navigation + prefetch | One deduplicated transport request; a superseding visit retains its page and resource. |
| Prefetch + newer visit | Late speculative resource data cannot replace newer state or poison either page cache. |
| Prefetch + mutation | A newer patch survives old prefetch completion; stale prefetched entries are not reusable. |
| Deferred + navigation | The old signal is aborted and its ignored-abort completion cannot replace the new value or shell. |
| Deferred + mutation | Mutation authority survives an older deferred completion. |
| Live + mutation | A late live refresh cannot replace a newer mutation patch. |
| Live + reconnect | The obsolete stream closes and old refresh work cannot replace post-reconnect state. |
| History + live | Repeated cached Back/Forward restores the correct manifest and ignores obsolete stream events. |
| Logout + pending work | Old visit, deferred, retry, prefetch, mutation, and stream work cannot restore state or redirects in the new session. |
| Destroy + pending work | Ignored-abort completions cannot write resource state or emit resource diagnostics after destruction. |

Additional cases protect mutation redirects across cached history restoration,
preserve caller errors while suppressing old resource diagnostics, and cover
navigation responses that arrive after newer mutations or resource refreshes.
Old omitted/error/deferred metadata cannot reset the newer resource, and
unrelated resources and the current navigation's page shell still apply.

## Findings and fixes

1. Resource-only loading lacked a lifecycle guard. A late generic resource
   response could write to a destroyed router, and old requests could emit
   success/error diagnostics after logout. Loads now capture the existing
   lifecycle generation and check it before settlement or error reporting;
   errors still reach the initiating caller.
2. Cached history restoration did not advance navigation authority. Pending
   mutation redirects could override newer Back/Forward navigation. Cached
   restoration now advances the same visit counter used for redirect ordering.
3. Full navigation responses unconditionally replaced resource state. Older
   page work could overwrite a mutation or refresh that became authoritative
   while it was in flight. Per-key tracking now distinguishes speculative
   prefetch epochs from authoritative epochs. Navigation accepts its shell and
   eligible resource keys while preserving newer authority and pending loads.

Resource versions remain opaque equality tokens, not ordered counters. Patch
hints retain their existing stale/canonical-refresh behavior. Page-cache
validity still requires coherent, ready, non-stale resource records.
