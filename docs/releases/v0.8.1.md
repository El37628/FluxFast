# FluxFast 0.8.1 Release Notes

> **Release theme:** Precise, convergent validation paths

FluxFast 0.8.1 is a compatibility-focused patch for the v0.8 validation system.
It keeps the `fluxfast/1` browser protocol and `fluxfast-schema/2` developer
manifest unchanged while making client and authoritative server errors identify
the same nested field.

## Nested authoritative errors

FastAPI/Pydantic locations now retain their complete path when FluxFast builds a
validation envelope:

```text
("body", "address", "postcode")
→ address.postcode

("body", "addresses", 0, "postcode")
→ addresses[0].postcode
```

`useForm` exposes these failures through the corresponding canonical
`form.errorMap` key. Multiple messages at one path remain ordered, root/model
errors retain the stable `general` fallback, and non-FluxFast requests keep
FastAPI's native validation response.

## Canonical numeric paths

`formatValidationPath()` now renders numeric array indices with brackets:

```text
v0.8.0  rooms.0.rate
v0.8.1  rooms[0].rate
```

The structured path remains `["rooms", 0, "rate"]`. Top-level error consumers
are unaffected; code that directly indexes a nested `errorMap` entry should use
the bracket form.

## Type and validator generation

Generated TypeScript contracts and native runtime validators are independent
outputs. If a validation-affecting JSON Schema keyword such as `uniqueItems`
cannot be enforced faithfully, FluxFast keeps the TypeScript type, omits that
contract's validator, and reports a diagnostic. Supported contracts continue to
generate normally.

The native runtime supports `date`, `date-time`, `email`, `ipv4`, `ipv6`, `time`,
`uri`, and `uuid`. Its default evaluator limits are `maxDepth: 64`,
`maxIssues: 100`, `maxOperations: 100,000`, and `maxProperties: 10,000`.

## Validation authority

Native client validation provides fast feedback and prevents structurally invalid
requests. FastAPI and Pydantic remain authoritative for every mutation, including
Python-only business rules. Browser coverage now proves the full boundary: a
client-invalid form sends no request, a structurally valid but server-invalid
nested value sends one request and maps to `address.postcode`, and a corrected
value succeeds on one subsequent request.
