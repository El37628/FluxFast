# v1.0 dependency freeze

The stable promotion uses the already-proven v0.9 dependency and tooling set.
This is a temporary release-preparation policy, not a promise to stop security
maintenance or a change to supported runtime/package ranges.

The reviewed starting point is `90c89ffba32e84996ed9f345a913ec512598c541`
(the merged v1.0 governance PR), based on the frozen v0.9.0 runtime.

## Update decisions

- Security corrections: review the advisory and affected paths, add regression
  coverage where applicable, validate, and merge in a separate PR.
- Necessary compatibility corrections: document the reproducer and why the
  current supported combination fails, validate, and merge in a separate PR.
- Routine patch/minor updates: consider individually; defer when there is no
  demonstrated release benefit. Availability and green checks alone are not
  sufficient reasons to change the candidate.
- Routine major updates, especially test/build tooling: defer until after 1.0
  unless security or supported-runtime requirements make them necessary.

There is no dependency auto-merge or protection bypass. Every accepted update
needs the normal required checks and a same-session review. Update this
inventory intentionally in that reviewed PR when a justified exception changes
the set; rerun the affected compatibility, lifecycle, performance, and packed
consumer evidence rather than treating earlier results as proof for new tools.

## Dependabot policy

Weekly version-update checks continue for npm, Python, and GitHub Actions.
Each ecosystem's `allow.update-types` permits patch/minor version updates,
and its explicitly version-only group contains patch/minor updates. Both are
needed: limiting a group alone would leave major updates eligible as individual
PRs.

GitHub documents that [`allow.update-types` applies only to version updates,
not security updates](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#update-types-allow).
Security updates stay enabled and remain independently eligible, including a
necessary major correction. The existing Node type-major ignore remains in
place to keep type coverage aligned with the oldest supported Node runtime.
No blanket version-range ignore, disabled schedule, or security-update grouping
is introduced.

After 1.0 publication and registry-backed validation, review removal of these
temporary patch/minor restrictions in a separate maintenance PR. Keep the
independent Node type policy unless the supported runtime contract changes.

## Initial security evidence — 2026-09-12

On the reviewed main commit, GitHub reported Dependabot security updates enabled
and zero open Dependabot alerts. A fresh `pnpm audit --audit-level high --json`
reported zero vulnerabilities at all levels. The Python audit used the same
pip-audit 2.10.1 version, target, and flags as CI, through an isolated tool
environment:

```bash
uvx --from pip-audit==2.10.1 pip-audit python/fluxfast --strict --progress-spinner off
```

It reported no known vulnerabilities. These are point-in-time observations,
not substitutes for PR checks or the final dependency/supply-chain release gate.
