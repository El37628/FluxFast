# FluxFast 1.2.0: React SSR and Vite

FluxFast 1.2 adds a complete React/Vite host alongside the existing Next.js host.
FastAPI remains authoritative for routes, authentication, authorization,
resources, mutations and validation. Both hosts use the same framework-neutral
Core runtime, React bindings and browser protocol.

These notes describe the **1.2.0 capabilities and distribution contract**.
Publication is complete only when the registry-backed release checks pass and
the GitHub release exists. A source version, merged PR or tag alone does not
mean packages have been published.

## Confirm publication

Check the [GitHub release](https://github.com/El37628/FluxFast/releases/tag/v1.2.0),
the [Python package](https://pypi.org/project/fluxfast/1.2.0/), and all six npm names:

```bash
npm view @fluxfast/core@1.2.0 version
npm view @fluxfast/codegen@1.2.0 version
npm view @fluxfast/react@1.2.0 version
npm view @fluxfast/vite@1.2.0 version
npm view @fluxfast/next@1.2.0 version
npm view @fluxfast/devtools@1.2.0 version
```

Each command must return `1.2.0`. A missing version is not an instruction to
install an older host and assume it supports the new APIs.

## New React/Vite application

Follow the [empty-directory React/Vite tutorial](../react-getting-started.md)
for backend/page code, typed resources, expected UI/API output and production
commands. Install matching Python and frontend packages:

```bash
python -m pip install "fluxfast==1.2.0"
# In the React frontend:
npm install @fluxfast/core@1.2.0 @fluxfast/react@1.2.0 react@19 react-dom@19
npm install --save-dev @fluxfast/codegen@1.2.0 @fluxfast/vite@1.2.0 vite@7.3.6
npm exec --no -- fluxfast-vite init --yes
```

From the backend project, run:

```bash
fluxfast types backend.main:app --frontend frontend --adapter react
fluxfast dev backend.main:app --frontend frontend
```

The browser uses one public origin for SSR documents, navigation, mutation
requests, deferred/live delivery and development HMR. Python starts the backend
privately and supervises both processes. Production startup consumes a checked
client/SSR artifact without source configuration or build tooling.

## What ships

| Package or capability | Purpose |
| --- | --- |
| `@fluxfast/react` | Shared resource/deferred/live hooks, forms, links, provider/root and server-rendering/hydration subentries. |
| `@fluxfast/vite` | React SSR host/plugin, installed-only init/generate/doctor, same-origin development HMR, production build and immutable startup. |
| `@fluxfast/codegen` | Framework-neutral schema/type/validator/route/mutation compilation and explicit Next/React registry targets. |
| `@fluxfast/core/server` | Server-only initial-page fetch, safe headers/redirects and streaming same-origin proxy primitives for adapter authors. |
| Python CLI | React/Vite host detection and supervision, adapter-aware type generation and production diagnostics. |
| DevTools | Shared React context; Next is optional in React-only applications. |

Use the [React API](../react-api.md), [Vite host](../vite-host.md),
[Codegen API](../codegen-api.md), and [adapter contract](../adapter-contract.md)
for detailed examples and ownership boundaries. Ordinary applications do not
need to implement their own fetch, proxy or hydration host.

## Existing Next.js applications

Keep `@fluxfast/next` imports, catch-all routes, configuration and initialized
scaffold. The adapter re-exports the same shared React objects; no component
migration or second provider is required. Its generator delegates shared work
to Codegen without changing the existing six-file Next artifact contract.

```bash
python -m pip install --upgrade "fluxfast==1.2.0"
# In the Next frontend:
npm install @fluxfast/next@1.2.0
# If these are already direct dependencies, update them too:
npm install @fluxfast/core@1.2.0
# Optional, only if used:
npm install @fluxfast/devtools@1.2.0
```

Regenerate contracts, run read-only checks, typecheck and rebuild before
production deployment. Do not add `@fluxfast/vite` to a Next frontend: two
declared host packages are ambiguous; use separate frontend projects instead.

## Compatibility and runtime requirements

- Python 3.11–3.14 and Node.js 22/24 remain supported. The Vite host specifically
  needs Node 22.12+ or 24, React/React DOM 19+, and Vite `>=7.3.6 <8`.
- Existing Next support remains `>=16.3.0 <17` with React 19+.
- `fluxfast/1` and `fluxfast-schema/2` are unchanged. Package and protocol versions
  remain independent. Older schema/1 manifests remain readable.
- The same-schema generated contract/fingerprint is unchanged. Producer metadata
  correctly reflects the installed Python version after regeneration; React's
  page registry uses React imports rather than the Next client directive.
- Existing Next applications are checked against actual published 1.0.1 and
  1.1.0 packages in both upgrade orders, the matched candidate and rollback.
  This does not make Python 1.1 a supported supervisor for the new React host.
- React shares Core's cache, mutation, deferred and live semantics rather than
  introducing another route table, resource store or protocol.

## Release verification and assets

The release gates install the actual checksum-verified candidate archives in
clean consumers outside the checkout. They cover SSR/hydration, no initial
refetch, first navigation, same-origin HMR, mutations, deferred/live behavior,
StrictMode, Redis workers, shutdown and immutable production execution after
source/build tooling removal. Separate post-publication consumers install only
registry packages; GitHub release creation waits for them and both historical
upgrade/rollback orders.

The GitHub release contains a Python wheel, Python source distribution, six npm
tarballs and `SHA256SUMS`. Verify the downloaded assets together:

```bash
sha256sum --check SHA256SUMS
```

Historical release snapshots remain immutable. See the
[release process](../releasing.md) for provenance, trusted publishers,
compatibility gates and recovery from interrupted publication.
