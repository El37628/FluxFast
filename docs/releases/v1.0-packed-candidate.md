# v1.0 packed-candidate gate

PR 20 proves the release candidate as distributions, not as a source checkout.
One workflow job builds and verifies exactly four files from the same commit:

```text
fluxfast-VERSION-py3-none-any.whl
fluxfast-VERSION.tar.gz
fluxfast-core-VERSION.tgz
fluxfast-next-VERSION.tgz
```

The verifier rejects missing or extra distributions, checks their metadata and
contents, and records all four digests in `SHA256SUMS`. The workflow uploads
that verified directory once. Both application consumers download it and check
the digests before installing anything, so a later job cannot silently rebuild
a different candidate.

## Isolated installation

Every distribution is installed. The source distribution is installed into a
dedicated temporary Python virtual environment, where the gate checks package
metadata, confirms that `fluxfast` imports from the isolated environment, and
runs the installed CLI. The realistic application consumer separately installs
the wheel with both npm tarballs into its own isolated Python and Node
environments. This avoids an overlapping wheel/sdist installation masking which
Python distribution supplied the package while still testing both formats.

No consumer imports the repository checkout. Candidate checks clear
`PYTHONPATH`, compare the installed Python and JavaScript versions, and use the
commands shipped by the installed packages.

## Complete production flow

The `Clean production consumer` job initializes a fresh Next.js application
from the wheel and tarballs, then exercises:

- schema and typed-contract generation, including the read-only drift check;
- TypeScript checking, optimized production build, and strict production
  diagnostics;
- the supervised one-origin production start, SSR, public health and readiness;
- cross-page resource reuse and known-version response omission;
- mutation behavior, client and server validation, and nested validation paths;
- deferred and live settlement, dynamic routing, navigation history, and clean
  shutdown without orphan listeners.

The installed candidate starts both the private FastAPI process and the public
Next.js process; the browser communicates through the single frontend origin.

## Packed distributed flow

The `Clean distributed consumer` job installs the same verified wheel and npm
tarballs, builds the generated application, and runs its frontend in production
mode. Against a real Redis service it starts three independent FastAPI worker
processes and proves:

1. worker A performs the initial deferred resource load;
2. worker B reuses the shared cached value without executing its loader;
3. a mutation routed to worker C invalidates the cache and publishes the live
   update;
4. browser clients converge on the new value across workers;
5. a subsequent worker reuses the refreshed shared cache;
6. the frontend, proxy, and all three workers stop on the graceful signal and
   release their listening ports.

The browser also checks one-origin transport, cross-page known-version
omission, generated server validation, and the distinct worker diagnostics.

## Continuous evidence

`.github/workflows/release-smoke.yml` owns the three-stage chain:

```text
Four-distribution contract
  |-> Clean production consumer
  `-> Clean distributed consumer
```

The two consumers depend on the artifact-contract job and download the named
`fluxfast-v1-candidate` artifact. `scripts/release-workflow.test.mjs` guards
that dependency, checksum verification, source-distribution installation,
production-mode distributed frontend, and graceful cleanup so the release gate
cannot regress to independent unverified builds.

This is a pre-publication gate. It does not bump the repository version or claim
that v1.0 has been published; those remain later release-plan phases.

## Local evidence

The candidate gate passed locally from one verified 0.9.0 pre-promotion build:

- all four distributions passed the release artifact verifier and their flat
  `SHA256SUMS` check;
- the source distribution installed and ran from a temporary Python 3.13
  environment;
- the full packed production consumer passed with Next.js 16.3.3;
- the packed distributed production consumer passed against Redis 8.10.1 with
  workers A, B, and C, then released all five listener ports;
- `pnpm typecheck`, 611 Core/Next tests, 65 release-policy tests, schema
  compatibility, and all five release-artifact tests passed.

The pull-request workflow repeats the candidate checks on GitHub-hosted Ubuntu
before merge; local evidence does not replace that required run.
