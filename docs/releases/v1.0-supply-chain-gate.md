# v1.0 dependency and supply-chain gate

This gate checks the frozen v0.9 candidate's dependency-security policy without
changing package constraints, resolved locks, protocol, schema, or public APIs.
It complements the [dependency freeze](v1.0-dependency-freeze.md) and
[security boundary audit](v1.0-security-audit.md).

## Mandatory checks

The PR security workflow and tag-release build use the same audit inputs:

```bash
pnpm install --frozen-lockfile
pnpm audit --audit-level high
python -m pip_audit --strict --progress-spinner off -r scripts/security-requirements.txt
```

The Python tool is pip-audit 2.10.1. The shared requirements file mirrors the
base runtime plus the optional Redis and development dependency groups, and
therefore resolves and audits their transitive dependencies. Listing those
dependencies directly also keeps the final unpublished candidate auditable:
pip-audit does not need to resolve `fluxfast==1.0.0` from PyPI before the release
exists. A regression test compares the list with `pyproject.toml` to prevent
drift. The earlier project-only audit omitted the optional dependency groups.

Both audit steps have a five-minute timeout and fail on audit-service errors.
The JavaScript audit fails on high/critical findings; the Python audit fails on
any known finding. There is no ignored advisory, ignored registry error,
`continue-on-error`, or success fallback. Retry an independently diagnosed
availability failure only after the service recovers; an unavailable audit is
not a clean audit.

Dependency Review still rejects moderate-or-higher findings introduced by a PR.
CodeQL still analyzes Python and JavaScript/TypeScript. These checks and both
dependency audits remain required by the protected-main ruleset. Publication
also waits for the existing production, integration, container, artifact, and
security gates; none is replaced by the local observations below.

## Regression coverage

`scripts/supply-chain.test.mjs` starts an isolated loopback audit endpoint and
invokes the real installed pnpm with each workflow's executable audit command.
It checks that a clean response succeeds, a completed HTTP 503 audit fails, and
parsed high/critical advisory responses fail. Each probe must actually issue an
audit POST and finish normally, not merely hit the test timeout. The outage
fixture separately reproduces the previous `--ignore-registry-errors` command's
incorrect success result. Synthetic advisories are test fixtures, not reports
of vulnerabilities in the reviewed dependency set.

The same test inspects every workflow's external action references, including
inline version comments and job-level reusable workflows. Mutable tags, branch
names, shortened commits, and dynamic references fail the pin check. Local
reusable workflows remain local references. The reviewed set contains 77
external references across nine workflows, representing nine distinct pinned
action references; all use full 40-character commit SHAs.

The audited action revisions are retained. There were no pending workflow-action
Dependabot PRs at this gate's start; a newer action is not accepted merely for
being available. Future updates need an independently reviewed PR and passing
checks under the dependency-freeze policy.

## Local evidence — 2026-09-14

On the supply-chain task branch based on main commit
`e6df9ed6a02d8e6b74c39a634c9e49299c980844`:

- `pnpm audit --audit-level high --json` succeeded: 184 dependencies and zero
  reported vulnerabilities at every severity.
- The expanded Python audit below succeeded on Python 3.13.14: 23 packages,
  zero known vulnerabilities, including Redis 8.1.0, httpx2 2.12.0, pytest 9.1.1,
  and Ruff 0.16.7.
- GitHub reported zero open Dependabot alerts. Pending dependency PRs had
  already been reviewed separately; no dependency update was added to this gate.
- `pnpm typecheck` passed. `pnpm test` passed 285 Core tests, 326 Next tests,
  57 tooling/release tests, and the schema/1 generate/typecheck/build consumer.
- The focused three-file regression suite passed all 19 tests with no skips.

```bash
uvx --from pip-audit==2.10.1 pip-audit --strict --progress-spinner off \
  -r scripts/security-requirements.txt -f json
node --test scripts/supply-chain.test.mjs scripts/release-workflow.test.mjs \
  scripts/dependency-freeze.test.mjs
pnpm typecheck
pnpm test
```

These are point-in-time results, not a promise that every historical version
allowed by the published dependency ranges is safe. JavaScript audits the
committed workspace lock; Python resolves the declared base and optional ranges
for the audit interpreter. The Python reference lock is not silently substituted
for that resolved environment. CI audits Python 3.14 for PRs and Python 3.12 for
tag builds, so their resolved versions may differ from this local observation.
Consumers must audit their own complete application dependency sets. A pinned
action revision prevents a mutable-reference change but does not establish that
the action or its downstream services are intrinsically safe. Fresh required
Dependency Review, CodeQL, and audit checks must pass on the final PR revision.
