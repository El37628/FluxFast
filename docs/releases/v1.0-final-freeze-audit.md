# v1.0 final freeze audit

This is the PR 21 compatibility review of `v0.9.0...a5ea091`, the complete
candidate through the packed-consumer gate. It is the decision record for
whether FluxFast may proceed to a version-only 1.0.0 promotion.

## Decision

**Pass.** The review found no unresolved P0 or P1 issue and no unreviewed public
API, protocol, schema, generated-contract, runtime, security, lifecycle, or
release-boundary change. The implementation differences from v0.9.0 are
corrective fixes already exercised by their focused gates. The 1.0 version
promotion may proceed, provided its semantic runtime digest remains unchanged.

## Protocol and schema

The shared `fluxfast/1` fixture digests remain byte-semantically identical to
the v0.9.0 snapshot. Both runtimes retain the media type, request headers and
bounds, capabilities, page and mutation envelopes, patch operations, and live
event contract. Package-version strings do not participate in protocol
interpretation. See the [protocol stability gate](v1.0-protocol-stability.md).

The producer remains the closed `fluxfast-schema/2` format, schema/1 remains
readable, and schema/3 remains explicitly unsupported. The stable application
fixture retains the same semantic fingerprint and generated contract. The only
expected manifest difference after promotion is producer package metadata; it
does not enter fingerprint canonicalization. See the
[schema stability gate](v1.0-schema-stability.md).

## Security and isolation review

The final boundary review covers tenant/user and anonymous/authenticated scope
transitions, header and schema parsing budgets, validation traversal budgets,
generated path containment, internal/external redirect rules, opaque Redis
topics, same-origin forwarding, and argument-array process execution. The
[security release audit](v1.0-security-audit.md) records the adversarial cases
and limitations. Dependency review, npm and Python audits, CodeQL for both
languages, action-SHA pinning, artifact verification, and protected-branch
checks were green on the candidate.

Authentication, authorization, CSRF, proxy trust, and application secret
handling remain application responsibilities; this is unchanged from v0.9.0.
Redis Pub/Sub remains ephemeral and reconnects recover from canonical state.
No security limitation introduced by the corrective diff is being deferred.

## Lifecycle review

Client stress covers AbortController ownership, prefetch and page-cache bounds,
resource subscriptions, live streams, reconnect timers, history listeners,
StrictMode remounts, logout, and router destruction. Server stress covers
application lifespan, concurrent/reentrant close, Redis connections,
subscriptions and handshakes, supervised descendants, Uvicorn workers, signals,
startup failure, and shutdown timeouts. All owned resources return to their
documented bounds or terminate; no unresolved leak or stale-authority race was
found.

POSIX process-group and Linux adoption tests are stronger than the available
Windows descendant proof, as documented in the server-lifecycle gate. This is
an existing platform limitation, not a new 1.0 regression or an unbounded
failure on the supported production path.

## Promotion constraint

PR 22 may update synchronized versions, producer metadata, the lockfile,
changelog, and release notes. It must not change runtime architecture or alter
the normalized runtime digest. If any later work changes a non-version runtime
source, re-open this audit, classify the finding, run its focused regression,
and repeat the full release gates before tagging.
