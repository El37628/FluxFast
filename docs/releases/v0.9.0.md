# FluxFast 0.9.0 Release Notes

> **FluxFast 0.9 freezes the public API and compatibility contract ahead of
> 1.0.**

FluxFast 0.9 is a stability release. It does not introduce a new adapter,
protocol, schema, routing model, or deployment topology. It turns the behavior
already built across the Python runtime, framework-neutral Core package, and
Next.js adapter into an explicit, tested contract for the 0.9 line and the
planned 1.0 release.

## Public API and versioning

The documented top-level Python exports, all 156 Core root exports, and all
five Next.js package entry points now have machine-checked inventories. Stable
and advanced stable candidates receive the same compatibility guarantee during
0.9.x. The established `useLiveStatus` hook and its status types are available
from the supported `@fluxfast/next/client` entry point.

`ValidationError` and `PageNotFoundError` are deprecated compatibility exports.
They remain importable through 1.0; applications should use FastAPI validation
and 404 handling or the specific FluxFast runtime error classes.

See the [stability contract](../stability.md),
[versioning policy](../versioning.md), and package inventories for
[Python](../python-api.md), [Core](../core-api.md), and
[Next.js](../next-api.md).

## Frozen wire and generated contracts

The browser wire contract remains `fluxfast/1`. Its envelopes, headers,
capabilities, redirects, live events, and mutation patch operations are frozen
as 1.0 candidates. The optional `appVersion` page metadata remains compatible.

Python continues to produce the closed `fluxfast-schema/2` developer manifest;
JavaScript tooling continues to read both schema/1 and schema/2. Manifest
fingerprints are deterministic. Generated filenames, exported names, naming
rules, semantic TypeScript types, and validators are covered by drift,
cross-runtime, and atomic-write tests.

## Runtime hardening

The release freezes and strengthens resource, mutation, cache/scope, deferred,
live, history, and lifecycle behavior. Notable hardening includes:

- bounded completed and in-flight prefetch state, with transport cancellation
  during eviction, logout, and router destruction;
- epoch-based race protection so older resource or prefetch responses cannot
  overwrite newer state or cache a stale page shell;
- session-safe mutation effects and navigation-safe redirects;
- bounded live delivery, reconnect resynchronization, listener cleanup, and
  Redis-backed multi-worker convergence; and
- stricter path, header, base64url, duplicate-key, control-character,
  validation-budget, redirect, and schema parsing checks.

The full [same-session freeze audit](v0.9.0-freeze-audit.md) records the reviewed
surfaces, resolved findings, and local evidence. It contains no unresolved P0
or P1 finding.

## Runtime and production support

The frozen support matrix is Python 3.11–3.14, Node.js 22 and 24, Next.js
`>=16.3.0 <17.0.0`, React 19+, and Redis 6.2–8.10 when Redis features are
configured. The supported production topology remains one public Next.js
origin with FastAPI on an automatically managed loopback port.

Release gates cover development and production browser flows, three-worker
Redis behavior, Docker and rootless Podman images and Compose deployments,
clean packed consumers, generated-code drift, both 0.8.1/0.9.0 upgrade orders,
rollback, dependency review, CodeQL, artifact contents, checksums, OIDC
publication, and registry-backed post-publication consumers.

Performance, retained-memory, bundle, code-generation, validation, Redis, and
production-startup measurements are repeatable diagnostics with correctness
gates. They establish the v0.9 baseline without turning host-specific timing or
byte observations into compatibility guarantees.

## Upgrade from 0.8.1

There is no required application rewrite. Upgrade the three packages together
for production:

```bash
python -m pip install --upgrade "fluxfast==0.9.0"
npm install @fluxfast/core@0.9.0 @fluxfast/next@0.9.0
```

Regenerate typed artifacts and run the production diagnostic:

```bash
fluxfast types backend.main:app --frontend frontend
fluxfast doctor --production --app backend.main:app --frontend frontend --strict
```

The unchanged browser protocol supports either Python 0.9.0 with JavaScript
0.8.1 or Python 0.8.1 with JavaScript 0.9.0 during a controlled rollout and
rollback. Matching 0.9.0 versions remain the recommended production state,
especially for supervisor-to-adapter production features.
