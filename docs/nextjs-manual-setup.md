# Manual Next.js Setup

Use `npx fluxfast init` for normal applications. This guide is the fallback for
custom monorepos, an unsupported `next.config` export, deliberate wrapper
ordering, CI debugging, or framework development.

The examples use a TypeScript project with a `src/` directory and the standard
`@/*` alias. Remove `src/`, use `.jsx`, and replace alias imports with relative
imports for a root-layout JavaScript project.

## 1. Create a client page

Create `src/flux-pages/home/index.tsx`:

```tsx
"use client";

export default function HomePage() {
  return <h1>Hello FluxFast</h1>;
}
```

FluxFast component names follow their path below `flux-pages`; this file is
`home/index`. A FastAPI page for `/` should therefore return:

```python
@flux.page("/")
async def home():
    return Page(component="home/index")
```

FluxFast pages run in the client runtime. Do not use Server Component APIs such
as `cookies()`, `headers()`, server-only imports, or async React components in
these files.

## 2. Connect the generated registry

Create `src/fluxfast.config.ts`:

```ts
import { defineFluxConfig } from "@fluxfast/next";
import { FluxApplication } from "@/.fluxfast/pages.generated";

export const fluxConfig = defineFluxConfig({
  application: FluxApplication,
});
```

The `.fluxfast/pages.generated.ts` file is framework-owned. Do not edit it by
hand.

## 3. Create the catch-all shell

Create `src/app/(flux)/[[...flux]]/page.tsx`:

```tsx
// GENERATED BY FLUXFAST.

import { createFluxNextPage } from "@fluxfast/next/server";
import { fluxConfig } from "@/fluxfast.config";

export const dynamic = "force-dynamic";

export default createFluxNextPage(fluxConfig);
```

Remove App Router pages that should be owned by FastAPI. In particular,
`src/app/page.tsx` takes precedence over the catch-all and shadows the FluxFast
`/` route. Preserve `layout.tsx`, global CSS, metadata, route handlers, and any
Next-owned routes you intentionally keep.

## 4. Wrap the Next config

For a normal ESM config:

```ts
import type { NextConfig } from "next";
import { withFluxFast } from "@fluxfast/next/next-config";

const nextConfig: NextConfig = {
  reactStrictMode: true,
};

export default withFluxFast(nextConfig);
```

For CommonJS:

```js
const { withFluxFast } = require("@fluxfast/next/next-config");

module.exports = withFluxFast({
  reactStrictMode: true,
});
```

If another plugin already wraps the config, choose the order deliberately:

```ts
export default withOtherPlugin(withFluxFast(nextConfig));
```

FluxFast cannot safely infer the correct order for an unknown wrapper, which is
why `init` reports a manual action instead of rewriting it.

## 5. Generate and validate

When the FastAPI application has typed resources, registered page parameters,
or JSON mutations, run from a Python environment that can import it:

```bash
fluxfast types backend.main:app --frontend frontend
cd frontend
npx fluxfast doctor
npm run build
```

This writes the backend manifest, generated resource models and key constants,
typed route and mutation helpers, and the page registry into the layout's
`.fluxfast` directory. To fail CI on either backend-contract or frontend-page
drift without modifying files, run from the parent directory:

```bash
fluxfast types backend.main:app --frontend frontend --check
```

For an untyped application or a deliberately split backend/frontend pipeline,
the frontend-only commands remain available from the frontend root:

```bash
npx fluxfast generate
npx fluxfast generate --check
npx fluxfast doctor
npm run build
```

If `doctor` reports that an existing catch-all is invalid, review the file and
preview the repair with `npx fluxfast init --dry-run --force`, then replace it
with the current template using `npx fluxfast init --force`. The flag changes
only how an existing catch-all is handled; the rest of the normal initialization
plan still applies.

Every generated artifact is deterministic. Regenerate after changing contracts,
registered FastAPI page or mutation signatures, or frontend pages;
`withFluxFast()` also refreshes the page registry when Next loads the config.
Do not edit `.fluxfast` output manually. See [typed resource contracts and code
generation](type-safety.md) for the lower-level schema-export workflow and
generated frontend APIs.

## Common failures

### Route returns the Next page instead of FluxFast

An App Router `page.*` owns that route before the optional catch-all. Remove or
relocate the conflicting route after preserving its component.

### Registry is stale

Run `npx fluxfast generate`. Never patch
`.fluxfast/pages.generated.ts` manually.

If `doctor` reports stale types, routes, mutations, or a schema fingerprint,
run `fluxfast types backend.main:app --frontend frontend` from the directory
that can import the backend application.

### Initial envelope returns 404

The browser path must match a FastAPI `@flux.page()` route. Also verify that the
backend app import passed to `fluxfast dev` is the application containing that
route.

### Component is not registered

`Page(component="rooms/index")` requires a corresponding
`flux-pages/rooms/index.tsx` or `.jsx` file. Component names are case-sensitive.

### Browser uses a second origin

For the standard setup, omit `clientUrl` and run:

```bash
fluxfast dev backend.main:app --frontend frontend
```

The frontend remains the only public browser origin. Configure `clientUrl` and
FastAPI CORS only when cross-origin deployment is intentional.
